# Release Leeway

Leeway ships via two GitHub Actions workflows that both trigger on a pushed
version tag (`vX.Y.Z`):

- **Release** (`.github/workflows/release.yml`, generated by dist) — builds
  binaries for macOS (arm64/x64), Linux x86_64-gnu, and Windows x86_64, and
  publishes a GitHub Release with archives, checksums, and the curl installer.
- **Publish to crates.io** (`.github/workflows/publish-crates.yml`) — runs
  `cargo publish --locked` to push the crate.

This skill performs a release end-to-end. Follow the steps in order and **stop
immediately if any preflight check fails** — do not push a broken or duplicate
release.

## Facts about this repo

- Crate/binary name: `leeway`. Manifest: `Cargo.toml` at the repo root.
- `origin` uses SSH (`git@github.com:nathanreyes/leeway.git`) — required so the
  push is allowed to touch `.github/workflows/`.
- Default branch: `master`. Tag format: `vX.Y.Z` (leading `v`).
- Repo slug for `gh`: `nathanreyes/leeway`.

## Argument

The invocation may include a version argument:

- `patch` (default if omitted) — bump the patch component (0.1.0 → 0.1.1).
- `minor` — bump minor, reset patch (0.1.0 → 0.2.0).
- `major` — bump major, reset minor+patch (0.1.4 → 1.0.0).
- An explicit `X.Y.Z` (e.g. `0.3.0`) — use exactly that version.

## Steps

### 1. Determine the target version

- Read the current version from `[package]` in `Cargo.toml`.
- Compute the new version from the argument (default `patch`).
- State clearly to the user: `current → new` and the tag that will be pushed.

### 2. Preflight — abort on any failure

Run these checks. If one fails, report it and stop; do not proceed.

- **Clean working tree:** `git status --porcelain` must be empty. If dirty,
  stop and ask the user to commit/stash first (a release commit should contain
  only the version bump).
- **On master, in sync:** current branch is `master`; run `git fetch origin`
  and confirm local `master` is not behind `origin/master`. If behind, stop.
- **New version is greater** than the current version.
- **Tag does not already exist:** neither `git tag -l vX.Y.Z` nor
  `git ls-remote --tags origin vX.Y.Z` returns the tag.
- **Version not already on crates.io** — this is permanent and can never be
  republished. Check the sparse index:
  `curl -s https://index.crates.io/le/ew/leeway` and confirm no line has
  `"vers":"X.Y.Z"`.

### 3. Bump the version

- Edit `version = "..."` under `[package]` in `Cargo.toml` to the new version.
- **Sync `Cargo.lock`** (critical — CI runs `cargo publish --locked`): run
  `cargo check` so Cargo rewrites the `leeway` entry in `Cargo.lock` to the new
  version. Then verify with `git diff Cargo.lock` that the *only* change is the
  `leeway` package's `version` line — if other dependency versions changed, stop
  and investigate rather than committing an unintended dependency bump.

### 4. Commit and tag

```sh
git add Cargo.toml Cargo.lock
git commit -m "Release vX.Y.Z"
git tag -a vX.Y.Z -m "Release vX.Y.Z"
```

### 5. Push (this fires both workflows)

```sh
git push origin master vX.Y.Z
```

### 6. Watch both workflows

Both runs start from the tag push. Watch each to completion:

```sh
gh run list --repo nathanreyes/leeway --limit 5
gh run watch <run-id> --repo nathanreyes/leeway --exit-status
```

- On success, confirm the crate is live via the sparse index
  (`curl -s https://index.crates.io/le/ew/leeway` shows the new `vers`) and
  report the Release URL and the three install commands.
- On failure, fetch logs with
  `gh run view <run-id> --repo nathanreyes/leeway --log-failed` and diagnose.

## Failure handling

- **crates.io publish fails but the binary Release succeeded** (e.g. token
  expired, transient error): fix the cause, then re-run just the publish with
  `gh workflow run publish-crates.yml --repo nathanreyes/leeway --ref master`
  (it publishes the current `master` version via `workflow_dispatch`). No new
  tag needed.
- **A version was already published to crates.io:** it can only be *yanked*,
  never replaced. Any redo requires a new, higher version — never reuse a
  version number.
- **Need to abandon a tag before its release finished cleanly:** delete it with
  `git push origin :vX.Y.Z` and `git tag -d vX.Y.Z`, delete the GitHub Release
  if one was created, then start over with a fresh version. Only safe if the
  crates.io publish did **not** already succeed for that version.
